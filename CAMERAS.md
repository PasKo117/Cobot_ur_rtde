# Три Hikvision: отдельное окно и PTZ

Обновление от 07.10.2026 для ветки `summertime`, исходный коммит
`2332a0ff3326ca91d07746b966579a82dd6531ad` (03.10.2026).
Проверенная пользователем схема RTSP перенесена в приложение: три независимых
потока, автоматическое переподключение, запасной поток 101 при недоступности 102.

## Установка обновления

1. Закройте приложение. Сохраните копию своей папки проекта.
2. Распакуйте содержимое `Cobot_hikvision_update.zip` **в корень проекта рядом с
   `app.py`**, с заменой файлов из архива. Это пакет изменённых файлов, а не весь
   репозиторий. Если вы дополнительно меняли локальный `app.py` после версии от
   03.10.2026, сравните его с новым перед заменой.
3. В терминале **того же интерпретатора Python**, на котором работал тест камер:

   ```bat
   python -m pip install -r requirements-cameras.txt
   python app.py
   ```

4. Откройте вкладку **«Камеры» → «Открыть окно камер и PTZ»**.

Адреса и ранее переданные учётные данные уже заполнены в `cameras.local.json`
в архиве. Этот файл хранит пароль открыто и исключён из Git через `.gitignore`.
В `cameras.example.json` находится шаблон без пароля. Для исходников из Git
скопируйте шаблон в `cameras.local.json` и заполните пароль самостоятельно.

Настройки читаются относительно папки модуля, а не текущего рабочего каталога.
Для сборки EXE файл `cameras.local.json` должен лежать рядом с EXE. Сборка EXE
в этом обновлении не проверялась.

Камеры можно открыть и самостоятельно, без основного приложения:

```bat
python camera_window.py
```

Старые `cam.py`, `camDiagn.py`, `camHirurg.py` и `ip_cam.py` теперь открывают это же
общее окно. Старый аргумент `ip_cam.py --pan` удалён. Для альтернативного файла
настроек: `python camera_window.py --config "C:\path\cameras.local.json"`.

## Окно и управление

Окно камер обычное, немодальное: его можно переместить за заголовок на второй
монитор и развернуть. В Windows также работает **Win + Shift + ← / →**.
Оно не закреплено поверх главного окна. Повторное нажатие кнопки в `app.py`
поднимает уже открытое окно. После закрытия его можно открыть снова.

По умолчанию три изображения расположены в один ряд. Кнопка **«Мозаика»**
перестраивает их в два столбца; **«В один ряд»** возвращает исходный вид.

| Элемент | Действие |
|---|---|
| `←` / `→` | Поворот выбранной камеры влево / вправо |
| `↑` / `↓` | Наклон вверх / вниз |
| Диагональные стрелки | Одновременный поворот и наклон |
| `+` / `−` под «Зум камеры» | Приближение / отдаление объективом камеры |
| `■` в центре стрелок | Остановить PTZ этой камеры |
| «Скорость PTZ, %» | Скорость команд камеры от 1 до 100; начальное значение 25 |
| «Стоп всех камер» или `Esc` | Остановить PTZ всех трёх камер, сохранив видео |
| Крестик окна | Остановить PTZ, отключить просмотр и закрыть окно |

**Стрелки и зум нужно удерживать мышью.** Отпускание, уход курсора с кнопки,
переключение фокуса в другое окно, сворачивание или потеря свежего видео
прекращают отправку движения и запрашивают остановку. После сетевой ошибки
для повторной попытки отпустите кнопку и нажмите её заново. Скорость PTZ
не связана с ползунком скорости роботов.

Камеры подписаны номерами и IP. Назначение «хирург/диагност/общий план» не
предполагается автоматически: при необходимости измените `name` в конфигурации.

## Подключение и PTZ

- Видео: RTSP/TCP, порт **554**, `/Streaming/Channels/102` и запасной `101`.
- PTZ: Hikvision **ISAPI через HTTP Digest**, HTTP-порт **80**, канал **1**.
- ONVIF этот модуль не использует; включённый ONVIF можно оставить как есть.
- В камере должен быть доступен ISAPI (в некоторых прошивках настройка называется
  Hikvision-CGI / Integration Protocol). Пользователю нужны права удалённого PTZ.
- Для первого запуска сохраните кодек, который уже работал в тесте; если есть
  проблемы с декодированием, попробуйте H.264 на дополнительном потоке без «+».

Модель имеет две механические оси — поворот и наклон — и 4-кратный оптический
зум; вращение вокруг оптической оси не добавлено. Кнопки зума отправляют команды
в камеру, а не обрезают картинку программно. Если цифровой зум разрешён самой
камерой, поведение на конце диапазона определяется её настройками.

Движение отправляется в `/ISAPI/PTZCtrl/channels/1/momentary`: каждый импульс
ограничен **350 мс**, пока кнопка удерживается, импульсы повторяются.
Остановка — нулевые pan/tilt/zoom в `/continuous`. Есть дополнительный контроль
обновлений GUI. Переход на неограниченное движение при ошибке не выполняется.
По спецификации камера сама прекращает импульс по времени; поддержку и
фактическую реакцию вашей прошивки нужно подтвердить на стенде.

Неудачная команда остановки отображается как ошибка PTZ. При сетевой задержке
уже отправленный импульс может завершиться позже отпускания кнопки; мгновенная
остановка без связи не обещается. При закрытии окно ждёт завершения команд до
4 секунд, не блокируя обработку событий Tk.

Параметры каждой камеры можно переопределить в её записи JSON:
`http_port`, `rtsp_port`, `scheme`, `channel`, `streams`, `username`, `password`.
Для HTTPS используйте `scheme: "https"` и правильный HTTPS-порт; проверка
сертификата включена. `invert_pan: true` / `invert_tilt: true` меняют направления
соответствующих стрелок, если установка или зеркалирование камеры этого требуют.
Переменные окружения `HIKVISION_USERNAME`, `HIKVISION_PASSWORD` переопределяют
учётные данные всех камер; поддержаны также прежние `COBOT_CAMERA_USER` и
`COBOT_CAMERA_PASSWORD` (HIKVISION имеет приоритет).

## Если видео есть, а PTZ не работает

Состояние видео и состояние PTZ выводятся отдельными строками под каждой камерой.

| Сообщение | Что проверить |
|---|---|
| `HTTP 401 / 403` | Логин, пароль и право PTZ; пользователь ONVIF и пользователь веб-интерфейса могут различаться |
| `HTTP 404 / 405 / 501` | Доступность ISAPI, HTTP-порт и поддержка `momentary` прошивкой |
| `камера отклонила momentary (код …)` | Сфотографируйте сообщение и пришлите версию прошивки; видео продолжит работать |
| `нет связи или таймаут` | Доступность веб-интерфейса камеры с этого ПК, её HTTP-порт и сетевое соединение |
| `не удалось подключить` | RTSP, учётные данные, поток 102/101 и кодек; остальные камеры продолжают работать |

Ошибка одной камеры не должна останавливать остальные или приложение. Чтение
видео и PTZ каждой камеры выполняются независимо в фоновых потоках; Tk обновляет
только последний кадр. Файлы видеозаписи не создаются.

## Что изменено и проверено

| Файлы | Назначение |
|---|---|
| `app.py` | Новая кнопка во вкладке камер, повторное открытие, остановка PTZ при выходе |
| `camera_window.py` | Отдельное перемещаемое окно, видео, стрелки, зум, две раскладки |
| `camera_backend.py` | RTSP, переподключение, Digest/ISAPI, ограниченные команды и остановка |
| `camera_config.py`, `cameras.example.json`, `cameras.local.json` | Настройки и адреса трёх камер |
| `cam.py`, `camDiagn.py`, `camHirurg.py`, `ip_cam.py` | Совместимые точки запуска нового окна |
| `requirements-cameras.txt` | Дополнительные зависимости |
| `tests/test_cameras.py` | 13 автономных проверок без оборудования |
| `README.md`, `STANDALONE_SCRIPTS.md`, `.gitignore` | Инструкции и исключение локального пароля из Git |

Методы управления роботами, джойстиками, маршрутами и регулятор скорости
роботов в `app.py` не менялись. `robot_control.py` и остальные модули роботов
не входят в пакет обновления. Старый `camera_view.py` остаётся в репозитории
для прежних внешних вызовов, новое окно его не использует.

Проверены синтаксис, независимый отказ RTSP, запасной поток, повторное подключение,
сериализация остановки после команды в полёте, истечение разрешения на движение,
ошибки HTTP/XML, Digest и XML через настоящий локальный HTTP-сервер, потеря фокуса,
устаревший кадр, запросы остановки при закрытии и повторное открытие из `app.py`.
Все **13 тестов пройдены**:

```bat
python -m unittest discover -s tests -p "test_cameras.py" -v
```

Графическая отрисовка под Windows, реальное PTZ, работа на втором мониторе и
совместная работа с физическими роботами здесь не проверялись. После установки
сначала проверьте короткие нажатия стрелок и зума на каждой камере при скорости
25%, затем отпускание кнопки и закрытие окна.
